# Presentation arrays: draggable vs not (Phase 9, audit row C8)

Every authored array from [research/09 §1](research/09-arrays-stega-inputs.md#1-array-inventory-for-drag-and-drop), classified after Phase 9. Paths are relative to `apps/web/src/`.

**How drag works here.** An element whose `data-sanity` path ends in an array item (`…[_key=="…"]`) gets a drag handle in Presentation; its siblings with the same array path are the drop targets. All annotations are draft-only (`getDataAttribute()` returns `null` outside draft mode), so published HTML has no `data-sanity`. Referenced items (`refs[]{_key, ...@->{…}}`) address the **authored reference item** on the owning document, not the referenced document; the stega text inside still opens the referenced document. Where stega text would fill the whole item (nav links, buttons) the label is `stegaClean`ed in draft, otherwise the text overlay registers on the same element and steals the handle.
